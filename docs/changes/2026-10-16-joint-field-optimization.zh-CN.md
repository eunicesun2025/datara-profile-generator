# 从现有提示词优化联合字段

支票的 `cheque_number`、`bank_sort_code`、`account_no` 共用同一条 MICR 读取和切分逻辑。以前导入器仅识别单字段标题，会把联合段落误归到前一个字段；优化器也只能追加单字段覆盖。现在可以将原文段落绑定为联合规则组，候选在原位置完整替换该段。

## 操作

1. 打开 Profile → 提示词优化 → 从现有提示词绑定联合规则。
2. 全文保持原样，选中共享段落，勾选至少两个 AI 字段，填写组名并点击“将选中文本绑定为联合规则”。
3. Cheque 示例可点“定位 cheque 联合段落”：识别 `【三个号码必须联合提取】` 至 `【其他字段】` 或 `3.8 Amount:` 之间的原文，再点击绑定。该按钮只定位已知标题，不改写文本。
4. 保存规则绑定并设为基线。选择任何成员会选中整组；取消任一成员会取消整组。
5. 为整组填写正确答案，运行优化。候选仅修改联合段落，组外的单字段仍可独立优化。候选通过最终复验后可手动发布，版本历史支持比较与回滚。

## 数据与约束

- `Profile.extraction_groups` 保存 ID、名称、成员字段 ID、当前规则 `extraction` 和原文锚点 `source_text`；旧 Profile 默认空列表。
- 初次绑定要求 `extraction == source_text`，原文在基线中只能出现一次，不允许范围重叠。同一字段仅属于一个组，成员必须是同表的 AI 字段。
- 绑定的组段落不参与单字段解析，避免污染前一个字段。成员的独立 extraction 清空，防止存在两份权威规则。
- 原文锚点保持不变，后续候选替换当前规则。所有替换按原始位置一次完成，不递归匹配新文本。找不到原文时阻止操作并要求重新绑定。
- 生成提示词由 `generators.py` 输出共享规则。Mapping、SQL、AI JSON 字段结构不增加组字段。
- 优化请求仍可传成员字段 ID，服务端自动扩展整组，检查每个样本的每行真值覆盖。模型使用 `candidate_group_rules` 返回整组新规则，禁止给成员单独生成覆盖。
- 组规则参与版本快照、哈希、提示词缓存、比较、发布及回滚；过期候选不能发布。

## 评估

保留逐字段准确率，同时增加 `failure_targets`（每组每张单据每次试验为一个单位，其他选中的单字段按原计数）以及每组的 `failure_groups` / `regression_groups`。组内全部成员及全部评分行正确、结构有效，才算该组通过。

接受候选以优化单位得分为主，不能用其他目标的改善抵消某组退步。保护集保留总体保护线，并检查每个联合组不退步。组规则差异卡显示整组得分；历史错误修订仍与实测提升分开标识。

## 验证和边界

新增测试覆盖无损绑定、原位替换、重复/缺失/重叠锚点、前一个字段污染、自动扩组选取、拒绝成员独立覆盖、过期哈希、整组计分、候选提取与最终复验、发布和回滚。真实浏览器验证了当前 cheque 提示词绑定和勾选联动。

这是手动原文绑定版本，不自动猜测任意大段提示词的语义归属。一个组目前绑定一段连续原文；非连续共享规则需要先整理为可审阅的连续段落并回归验证。传统非分组字段暂沿用原来的追加覆盖机制。没有将 MICR 裁图或专用 OCR 接入生产提取路径。

测试中的模拟模型仅验证流程，不能证明真实 Qwen 识别精度。实际 cheque 模型测试记录留在本机 `data/optimizer`，不得提交真实支票、账号、密钥和测试导出到版本库。

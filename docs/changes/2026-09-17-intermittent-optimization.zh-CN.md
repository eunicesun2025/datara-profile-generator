# 偶发提取错误：历史证据与重复实测分开

## 问题

同一份单据以前出错，这次却提取正确。旧逻辑用用户粘贴的错误替换基线分数，可能把实际原版和候选都成功的一次测试标为从 0% 提升至 100%。

## 当前设计

- 历史错误仅给优化分析提供证据，不作为本次评分样本。原版与候选分别实际提取。
- 优化工作台默认每案例 3 次，支持 1–10 次；API 参数 `evaluation_repeats` 默认 1，保留旧调用成本。原版、每轮候选、最终验证使用同一次数和配置。
- 多次测试禁用缓存，包括之前存在的基线缓存。每次重复有独立原始输出、评分、耗时、重试次数和 repetition 编号。连接失败后的重试不算新样本。
- 不同案例仍受 extraction_concurrency 限制；单案例的重复依次执行。失败或取消会停止同阶段未完成请求。
- 历史错误可在已有案例中补充、修改或清除。数据经过现有答案结构校验，仅影响新任务，已有任务保存的快照不变。
- 无实测错误、也无相关历史错误时停止，不编造改进理由。存在历史错误时可生成候选；实测无正向提升时保留候选供查看，但不可发布，即使 minimum_improvement 为 0 也不能靠平分通过。
- 指标准确率按各次测试的被评分字段计算；案例通过次数则要求该次所有被评分字段正确。修复结果汇总要求该路径每次复验均正确，不因最后一次刚好成功就算完全修复。
- 多次全对不是长期成功概率或统计显著性证明；可增加次数与代表性保护案例。没有历史错误时不能伪造一份来驱动优化。

## 使用

1. 进入提示词优化，选择目标字段。
2. 在待修复案例上点击「编辑历史错误」，粘贴该样本在原提示词下实际出现的错误 JSON；已有正确答案保持正确。
3. 默认每案例重复 3 次，也可增加至 5 或 10 次，启动前会显示预计常规调用数。
4. 查看基线、候选和最终验证的每案例通过次数。只有实测提升达到门槛、保护案例通过、最终复验通过且 Profile 未变化，才允许发布。

这些测试仍调用外部模型；网络中断会单独报失败，不当作字段识别错误。当前没有完整断点续跑或统计置信检验。本地验证使用模拟端点和合成样本，不代表真实 Qwen 或企业网关验证。
